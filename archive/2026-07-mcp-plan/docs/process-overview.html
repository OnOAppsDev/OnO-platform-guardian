Marketplace Change Propagation — Versioning Strategy

When Marketplace version changes, the plugin detects it at session start and applies a tiered response based on semantic version bump type. Developers see exactly which domains changed before any work begins.

MAJOR v2.0.0 Breaking change — existing standard replaced or removed
Plugin behavior: BLOCKS all feature development until re-audit complete
Required action: Full Phase 2 re-audit for affected domains. PM acknowledgement required.
Deadline: 14 days. After deadline, emergency-bypass is required to continue.
MINOR v1.3.0 New standard added or existing one significantly updated
Plugin behavior: WARNS on session start. Shows domain-level diff of what changed.
Required action: Acknowledge changed domains. Targeted re-check (not full re-audit) of affected areas only.
Deadline: 7 days to acknowledge. Shown as reminder every session until resolved.
PATCH v1.2.3 Clarification, typo fix, non-breaking addition
Plugin behavior: NOTIFIES once (non-blocking). Shown once at first session of the week.
Required action: Read and mark as seen. No re-audit required.
Deadline: None.

"Implement the Continue Watching row"
