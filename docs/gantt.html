Notes & Key Dependencies
SC-1 (org-level vs. project-level settings) must complete before M1 reaches CLAUDE.md generation (~W5–W6). SC-2 (auto-review agent decision) is independent — can be done any time W1–W2.
Governance Q&A (OQ-1–4) are stakeholder decisions: who has write access to Repo B, version upgrade policy, escalation path, notification channel for emergency bypasses. Must be resolved before M5 pilot. Schedule these meetings early — they don't block plugin code but block going live.
Org Knowledge / Marketplace track is stakeholder-owned and runs in parallel with the technical track. PM, Design Lead, and Architects must contribute. Delays here push M5, not M1–M3.
Marketplace Gap Audit is blocked until repo access is granted. Once done, its findings will revise M4 scope — the current 6-session estimate is a floor. Empty plugin effort is shown as TBD and will be sized after the audit.
M2 (Audit Engine) can begin as soon as M1's knowledge connector is complete (approximately mid-W5). The 1-week overlap shown between M1 and M2 is intentional and safe.
M5 pilot requires both tracks to converge: plugin complete (M1–M3) + org knowledge substantially populated (M4). If M4 slips, M5 slips. The technical track is not the bottleneck.
Rollout to remaining 6 platforms begins after iOS Mobile pilot retrospective is complete. Not shown — this is a separate 12-week planning window after the pilot.
